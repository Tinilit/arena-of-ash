# Architecture

`main.ts` owns one Phaser game and destroys it on hot replacement. `app/config.ts` defines a 1280×720 logical area with FIT scaling, WebGL preference/Canvas fallback, and six scenes. Boot loads `Services` into the Phaser registry; it owns the player and SaveStore. Appearance is fixed to Ash Vanguard and motion to Grounded, independently of any obsolete browser preference values.

Scene flow: Boot → MainMenu → Arena / Character / Shop. Arena → Victory collection → Result → MainMenu / Arena, or automatic Result after defeat/draw. Escape returns to camp and abandons unresolved combat. There is no studio or style-selection scene.

`domain` defines player identity, inventory, equipment, fixed combat baselines, transactions and opponent progression. The external JSON has twelve default equipment definitions; `data/catalog.ts` exposes the installed session catalog, enemy rank names and rewards. `domain/opponents.ts` generates compatible random loadouts from the active catalog using victory count and an injected RNG. Pure `combat/realtime.ts` owns continuous fighter state, independent hand actions/cooldowns, body actions and knockdown rules, movement, jumping and outcomes. `combat/geometry.ts` handles moving capsule contact; `ArenaAI.ts` chooses movement/actions. None imports Phaser.

Battle flow is Fighting → Victory / Defeat / Draw. ArenaScene accumulates frame time into 120 Hz substeps, capped at 100 ms per rendered update to avoid fast-forwarding through a suspension. Each step advances both fighters, composes and renders their poses, then reads actual world-space body/blade geometry. Contact resolution sweeps both moving shapes over the same interval and applies damage only in active swing windows. A swing ID and hit flag prevent repeated damage. Both contacts in a simultaneous trade resolve before choosing an outcome. Animation impact markers do not apply damage. Rewards are persisted before ResultScene and use battle IDs to prevent duplicate payouts.

`characters/ArenaMotion.ts` layers action torso/weapon targets over locomotion legs and the passive arm. Ballistic jump height lives in the pure fighter state rather than in a second visual-only displacement. The original cutout shoulder hierarchy, fixed bone lengths, free-arm depth, future front-hand attacks and camp previews remain. Scene shutdown clears keys, pointer holds and focus handlers. Focus loss pauses combat; resume starts with no accumulated simulation backlog.

`characters` owns the articulated rig, pure keyframe playback, constrained two-bone IK and equipment-specific spear motion. `rendering` owns procedural Ash artwork and gear adapters. `ui` provides buttons, panels, bars and English strings. Scenes coordinate those components without duplicating damage formulas. Phaser scene-local objects/timers/tweens are disposed on shutdown; keyboard listeners and animator callbacks are explicitly cleaned up.

Persistence key: `arena-of-ash.v3`, format `{version:3,player:Player}`. Saved data includes identity, gold, owned item IDs, equipped slots, opponent progression and reward IDs. Derived stats, battle HP and visual state are omitted. Essential fields, known catalog references and ownership are validated. Missing, malformed or unsupported saves use a default warrior. Storage exceptions preserve session play with a warning. Version 2 saves with valid current equipment retain their remaining fields; removed attributes, XP, levels and points are discarded. No retired-equipment or appearance-setting migration is provided.

Shop and inventory page their lists without changing definitions or ownership. New equipment extends the catalog and renderer; art replacement preserves pivots and leaves game rules untouched. The read-only development snapshot is unavailable through the production entry point. See [animation](ANIMATION_SYSTEM.md), [anatomy](ANTHROPOMETRY.md), [equipment](EQUIPMENT.md) and [art contract](ART_PIPELINE.md).

## Runtime catalog

Boot fetches and validates `public/content/items.json`, installs a session catalog, decodes optional item images, then loads the player save and starts camp. Gameplay rules keep synchronous catalog lookups. `src/content/schema.ts` is independent of Phaser; `loadCatalog.ts` owns timeout/fallback behavior; `textures.ts` registers runtime artwork. `src/data/catalog.ts` retains opponent/reward definitions and the catalog lookup API. The JSON imported at build time is only an included fallback. See [runtime content](RUNTIME_CONTENT.md) for the separate publication path.

## Display density

`app/display.ts` manages physical canvas size, camera zoom and text raster resolution while retaining 1280×720 world coordinates. Every scene prepares its camera before creating content; the shared label factory registers text for density changes and removes destroyed labels. Window resizing and DPR changes update existing scenes without recreating combat or player state. Graphics render at the higher backing resolution; label textures are rerasterized rather than enlarged from a 1× bitmap. See [display scaling](DISPLAY_SCALING.md).

Equipment positions (`EquipmentSlot`) are separate from item categories (`Slot`). `slotCategory` validates helmet/body/hands/belt compatibility. Equip moves an owned ID between positions; duplicate equipped instances are invalid. `primaryWeapon`/`primaryHand` are shared by stats, rig, action poses, AI range and collision eligibility. `stats(player, hand)` counts that action's chosen hand weapon and worn armor. Other hand weapons and belt attachments do not stack into the action. Throw previews use a single release marker, open-hand state and a harmless training prop, without starting an arena action.

Combat geometry carries per-hand blade/fist capsules and per-foot boot capsules. `Swing.hand` selects the exact rendered branch. Pain/stagger state, stun/cooldown timers and push velocity are pure combat state; `ArenaMotion` composes their visible response without changing stats or awarding damage.

`combat/projectiles.ts` advances independent released-item poses and builds damaging blade/head capsules. The realtime resolver spawns from rendered grip geometry, sweeps projectiles against moving bodies, and applies one contact. It records item consumption at a throw release or potion sip; ArenaScene immediately mirrors this into persistent ownership and saves. `drinkMotion.ts` supplies the same rear-hand animation to belt use and harmless camp/Character previews.

`domain/inventory.ts` stores total counts separately from unique catalog IDs and slot references. Backpack availability subtracts equipped copies; each slot reserves one. Save v3 accepts optional quantities (missing means one) and validates occupied counts against ownership. Bulk purchases are atomic and only apply to consumables.

The pure resolver records `collectedItems` alongside exact-source consumption events. Landed projectiles transition once to pickedUp and transfer ownership, even from enemies. Scene cursors persist each event once. `combat/parry.ts` holds precision timing; contacts drive parry success and a one-second attacker stun, without range-based hit shortcuts. A separate seeded AI stream controls rare weapon throws.
